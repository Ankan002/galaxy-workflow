# Product

## Register

product

## Platform

web

## Users

aakriti is built for **creators and developers, both first-class**: people wiring text · image · video · LLM pipelines on a canvas. The creator wants to produce content — social posts, edited media, generated copy — without writing glue code; the developer wants explicit control over models, configs, and execution internals. They meet in the same node graph, so the interface must read to a non-engineer and still expose the detail an engineer expects.

The working context is deliberate desktop craft: the app gates viewports below the desktop breakpoint, because building a DAG needs a bigger canvas. Users arrive to assemble something — drag nodes, connect handles, configure, and run — not to browse.

There is also a lighter marketing/entry surface (dashboard, template library, first-run) that speaks to prospective users before they've built anything. The primary register stays **product** — the canvas and app shell are the point — but that entry surface should carry the same identity with a touch more warmth and invitation.

## Product Purpose

aakriti (आकृति, "form / shape") is a visual AI workflow builder: discrete nodes woven on an infinite canvas resolve into *form*. Users compose pipelines from text, image, video, LLM, crop, and frame-extraction nodes, then run them — as a single node or the full DAG — with execution handled durably in the cloud and status surfaced near-real-time.

Success is **a pipeline that runs**: the user builds a multi-node flow, connects it, hits run, and watches it execute to completion with legible per-node status and output. Every screen should shorten the path from blank canvas to a flow that produced something.

## Positioning

Weave AI into form: aakriti turns scattered AI capabilities into a single crafted pipeline you assemble and watch run — a warm, editorial workspace where building the graph feels like craft, not configuration.

## Brand Personality

Warm, crafted, calm, precise, culturally rooted, editorial. The voice is quiet and confident — it never shouts to prove it's powerful. Warmth comes from paper/ink editorial restraint and the Devanagari आ mark, not from decoration. Precision shows in hairline structure and legible execution state. The feeling to evoke: the calm of a well-set page, plus the quiet satisfaction of watching parts resolve into a working whole.

## Anti-references

Do not look like cold SaaS: no gradient chrome, no neon, no glassmorphism, no generic "AI sparkle" iconography, no loud glowing accents. Avoid the busy node-editor cliché where every wire and card competes for attention. Warmth and identity must never tip into skeuomorphic kitsch or ornamental Devanagari — the आ is a mark, not a garnish.

## Design Principles

Form from parts: the core metaphor is आकृति — assembly is the product. Make wiring nodes feel like deliberate craft, and make the resolved whole legible, not just the pieces.

Quiet confidence: ink and paper carry ~95% of the surface; marigold appears once or twice. Restraint is the default; emphasis is earned through weight, space, and hierarchy — not color or glow.

Trust through visibility: execution is the moment of truth. Node status, running state, and outputs must be immediately legible and honest — a run you can watch and believe is worth more than a faster one you can't.

Culturally rooted, not decorated: the Devanagari आ and the warm editorial palette are identity, not ornament. Reach for meaning over the generic AI-tool aesthetic every time.

Desktop craft surface: this is a precision workspace for a bigger canvas. Favor density, alignment, and control over mobile-first compromise — while keeping the dashboard and first-run inviting to newcomers.

## Accessibility & Inclusion

Target **WCAG AA**: body text ≥ 4.5:1 against its ground (watch the warm near-white paper — muted grays wash out on it), large text ≥ 3:1, visible keyboard focus (the marigold ring), and full `prefers-reduced-motion` alternatives for the pulsating run glow, animated edges, and any reveal motion. Canvas data-spectrum colors (indigo · vermilion · peacock · leaf · rani · sky) must never be the only signal for a node/connection type — pair them with label or shape so color-blind users aren't excluded.
